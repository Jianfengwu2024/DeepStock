# PathEfficiencyFK 六窗口对比设计

## 目标

一次提交 90、60、40、30、20、10 日六个 PathEfficiencyFK 样本外任务，并在同一页面比较它们的交易表现和预测质量。

## 约束

- 六个子任务使用同一数据集、股票、日期、FK 参数、交易成本和随机种子，只改变 `topology_lookback_sessions`。
- 子任务继续使用既有预计算缓存和既有命令，不复制模型实现。
- 每个子任务仍是普通任务，可以单独查看完整结果。
- 任一子任务失败不阻断其余任务；批次页面显示失败原因。
- 对比页只读取各子任务的 `boundary-policy-evaluation.json` 和 `feynman-kac-predictions.json`。

## 数据结构

新增持久化的 `ComparisonRecord`，保存批次 ID、名称、创建时间、状态、六个窗口对应的子任务 ID。批次文件位于任务根目录下的 `_comparisons`，服务重启后仍能恢复。

`ComparisonManager` 只负责创建、列出、读取和删除批次；实际排队与执行仍由 `JobManager` 负责。删除批次默认只删除批次索引，不删除六个可复用的子任务。

## API

- `POST /api/comparisons`：接收一份 PathEfficiencyFK 配置，创建六个互斥名称的子任务。
- `GET /api/comparisons`：列出批次及完成进度。
- `GET /api/comparisons/{id}`：返回六个窗口状态、关键指标和净值序列。
- `DELETE /api/comparisons/{id}`：删除批次索引。

批次状态由子任务实时归纳：全部排队为 `queued`，存在运行任务为 `running`，全部结束且至少一个成功为 `completed`，全部失败或取消为 `failed`。

## 页面

PathEfficiencyFK 配置区增加“运行六窗口对比”按钮。主工作区增加“窗口对比”入口和独立对比视图：

- 顶部给出最佳收益窗口、最低回撤窗口、最高方向正确率窗口和完成进度。
- 表格按 90、60、40、30、20、10 日展示成本后收益、最大回撤、方向正确率、均衡正确率、平均仓位和换手。
- 一张图叠加六条成本后净值曲线。
- 每行提供“查看完整结果”，切回对应普通任务。
- 页面结论使用直白中文，不把 Brier、ECE 等技术术语放在首屏。

## 验证

- 单元测试覆盖批次创建、固定窗口、名称互斥、状态聚合、失败隔离和持久化恢复。
- API 测试覆盖数据集注入和对比指标响应。
- 静态测试覆盖入口、对比表、净值画布和跳转行为。
- 在 145 上使用半导体板块真实运行六个窗口，核对六个子任务只有窗口参数不同，并留下对比结果。
